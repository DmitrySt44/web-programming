# Как проект переделан по схеме с лекции

Каждый шаг — отдельный коммит (`git log`, `git show <коммит>`). Каждый шаг можно запустить и проверить, прежде чем идти дальше.

## Словарик

- **Интерфейс** (в коде это абстрактный класс `ABC`) — список методов без начинки. Он говорит: «любой, кто хочет быть хранилищем, обязан уметь вот это». На схеме это `I...`: `IStudentRepo`, `IStudentService`.
- **Реализация** — класс, который наследует интерфейс и пишет начинку методов (`JsonStudentRepo`, `NaiveStudentService`). На схеме это стрелки от `IRepo` к `json`, `postgres`, `mysql`.
- **Конструктор** (`__init__`) — метод, который запускается при создании объекта. Через него объект получает всё, что ему нужно для работы.
- **Внедрение зависимостей** — класс не создаёт нужные ему детали сам, а получает их в конструктор снаружи. На схеме: `Controller(s: IService)` и `ns = new naiveService(ur)`.

## Схема слоёв

```
браузер ──HTTP──▶ StudentController ──▶ IStudentService ──▶ IStudentRepo ──▶ students.json
                  (controllers.py)      (services.py)       (repositories.py)
```

Каждый слой знает только про интерфейс слоя под собой, поэтому любую деталь можно заменить, не трогая остальные.

## Было

Всё в одном `main.py`: чтение и запись `students.json`, проверки и адреса запросов.

## Шаг 1. Репозиторий (`repositories.py`)

Репозиторий отвечает на вопрос «где и как хранятся студенты». Всё, что работало с файлом (`load_data`, `save_data`, `next_id`), переехало из `main.py` в класс `JsonStudentRepo`. Рядом лежит интерфейс `IStudentRepo` с методами `get_students`, `get_student_by_id`, `add_student`, `update_student`, `delete_student`. Это то же, что `getUsers`, `getUserById`, `addUser` на схеме.

`main.py` создаёт `repo = JsonStudentRepo("students.json")` и вызывает его методы. Поведение сайта не изменилось.

## Шаг 2. Сервис (`services.py`)

Сервис отвечает на вопрос «что приложение делает со студентами». Класс `NaiveStudentService` получает репозиторий в конструкторе (`IService(r: IRepo)` на схеме) и пока просто передаёт ему вызовы. Зачем нужен такой «пустой» слой: позже сюда можно положить правила (например, запретить двух одинаковых студентов в одной группе) в виде `AdvancedStudentService`, не трогая ни контроллер, ни хранилище.

В `main.py`: `service = NaiveStudentService(repo)`.

## Шаг 3. Контроллер (`controllers.py`, `models.py`)

Контроллер отвечает на вопрос «как приложение принимает запросы из браузера». Все адреса `/students` собраны в класс `StudentController`, который получает сервис в конструктор (`Controller(s: IService)`). `StudentIn` (описание того, как должен выглядеть присланный студент) переехал в `models.py`.

`main.py` теперь только собирает детали по цепочке, как внизу схемы:

```python
repo = JsonStudentRepo("students.json")
service = NaiveStudentService(repo)
controller = StudentController(service)
app.include_router(controller.router)
```

## Шаг 4. Вторая реализация (`InMemoryStudentRepo`)

Проверка, что схема работает: появился второй репозиторий, который хранит студентов в памяти. Чтобы переключиться на него, в `main.py` меняется одна строка: `repo = InMemoryStudentRepo()`. Сервис и контроллер не меняются. Так же потом добавляются `PostgresStudentRepo` и `MySqlStudentRepo`: тот же набор методов, другая начинка.

## Шаг 5. Обновление в реальном времени (`realtime.py`)

Обычный запрос работает так: браузер спрашивает, сервер отвечает, всё. Сервер сам написать браузеру не может. **WebSocket** — это соединение, которое остаётся открытым, и по нему сервер может писать браузеру в любой момент.

- `ConnectionManager` запоминает все открытые страницы и умеет написать им всем (`broadcast`).
- В `main.py` появился адрес `/ws`, куда страница подключается при открытии.
- После добавления, изменения и удаления контроллер вызывает `broadcast("changed")`.
- В `index.html` страница по сообщению `changed` заново загружает список. Если связь оборвалась, страница переподключается через 2 секунды.

Проверить: открыть сайт в двух вкладках, добавить студента в одной, во второй он появится сам.

Заодно в `index.html` добавлено экранирование имён: раньше вставка имени через `innerHTML` позволяла записать в имя HTML-код, а теперь он дошёл бы до всех открытых страниц.
